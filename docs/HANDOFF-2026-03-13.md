### 3. Mobile Login Bug (Fixed)
**Problem:** Login form fields didn't appear on mobile.

**Root causes found:**
1. `useIsMobile()` initializes as `false` → first render shows 2-column desktop grid on mobile. If JS hydration is delayed, form is squished into a ~188px column
2. No explicit viewport meta tag → some mobile browsers render at 980px width, media queries never match
3. `overflow: hidden` on grid container clipped form content

**Fix:** Rewrote LoginPage to use **CSS media queries** for layout instead of JS. Both branding panels are always in the HTML; CSS shows/hides the correct one. Form is always visible regardless of JS state.

## Architecture Decisions Made

1. **CSS over JS for login layout** — Eliminates hydration race condition. Login must work even if JS fails.
2. **Shared `useIsMobile` hook** — 768px breakpoint via `matchMedia`. Used for non-critical layout adjustments (sidebar drawer, chart sizing), NOT for content visibility.
3. **`.modal-body` CSS class** — All modals use this for responsive width. Applied to: EnvironmentAlignment, VoiceJournal, LeadershipTips, TeamSummary, CompareWithOthers, EnvironmentReport, FrictionMap, BridgeWizard.
4. **Inline styles preserved** — Didn't migrate to Tailwind classes. Existing pattern works; migration is a separate task.
